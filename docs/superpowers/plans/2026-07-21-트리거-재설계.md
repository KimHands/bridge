# 트리거 알고리즘 재설계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 작동하지 않는 mood 가중치(no-op)를 제거하고, JITAI 근거 기반의 명시적 게이트 체인(G1~G5)으로 트리거를 재설계해 mood_score가 실제로 발동을 좌우하게 만든다.

**Architecture:** 신호 계산을 DB 없는 순수 함수 모듈(`trigger_signal.py`)로 분리하고, `routine_trigger.py`는 게이트 체인 오케스트레이션만 담당한다. 가중합 대신 "키워드 반복 AND 개인 기준선 대비 mood 편차"를 독립 게이트로 적용하며, 모든 무발동 결정을 익명 카운터로 계측한다.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy 2.0(async), Alembic, pytest / pytest-asyncio, PostgreSQL 16

## Global Constraints

- 설계 문서: `docs/02-design/2026-07-21-트리거-재설계.design.md` — 파라미터·근거는 이 문서가 단일 출처.
- **임상 임계치·구간명을 사용하지 않는다.** 개인 기준선(본인 과거 기록) 기반만 허용.
- 계측은 **익명 사전집계**만 — `user_id`를 저장하지 않고 `(outcome, day_bucket, count)` 1행만 누적.
- 계측 실패가 트리거 본 로직을 절대 깨뜨리지 않는다 — 독립 세션 + 예외 삼킴 (`safety_metrics.py` 패턴 준수).
- 일자 버킷은 **KST 기준**으로 Python에서 계산한다(방언 안전).
- `run_trigger`는 요청 세션을 쓰지 않고 자체 `AsyncSessionLocal`을 쓴다 — 기존 동작 유지.
- 파라미터 확정값: `TRIGGER_THRESHOLD=3`, `LOOKBACK_DAYS=7`, `COOLDOWN_DAYS=3`, `WEEKLY_ASSIGN_CAP=2`, `WEEKLY_WINDOW_DAYS=7`, `MIN_BASELINE_OBS=7`, `BASELINE_WINDOW=30`, `MIN_MOOD_STDEV=0.5`, `MOOD_SENSITIVITY_L=1.0`
- 테스트는 컨테이너에서 실행: `docker compose exec -T api python -m pytest ...`

```python
"""트리거 신호 계산 — DB 접근이 없는 순수 함수.

설계: docs/02-design/2026-07-21-트리거-재설계.design.md
기존 가중합(mood 0.3 + 키워드 0.7)은 모든 키워드에 동일 상수를 더해
발동·순위 어디에도 영향이 없는 no-op이었으므로 폐기한다. 키워드 반복과
mood 편차를 독립 게이트로 분리한다.
"""

TRIGGER_THRESHOLD = 3  # 최근 7일 내 동일 키워드 발생 횟수


def count_keyword_frequency(diary_logs: list[dict]) -> dict[str, int]:
    """diary_logs: [{"mood_score": int, "emotion_keywords": [str]}] → 키워드별 발생 횟수."""
    freq: dict[str, int] = {}
    for log in diary_logs:
        for keyword in log["emotion_keywords"]:
            freq[keyword] = freq.get(keyword, 0) + 1
    return freq


def select_candidate_keywords(keyword_freq: dict[str, int], limit: int = 2) -> list[str]:
    """임계 이상 키워드를 빈도 내림차순으로 최대 limit개.

    동점은 키워드명 오름차순으로 깨 결정성을 보장한다(가짜 정밀도 없이 정직한 순위).
    """
    candidates = [k for k, f in keyword_freq.items() if f >= TRIGGER_THRESHOLD]
    return sorted(candidates, key=lambda k: (-keyword_freq[k], k))[:limit]
```

"""트리거 결정 익명 계측 — best-effort 사전집계 카운터.

트리거 본 로직을 절대 깨뜨리지 않는다: 독립 세션 + 예외 삼킴
(app/services/safety_metrics.py와 동일 철학).
"""
import logging
from datetime import UTC, date, datetime

from app.core.database import AsyncSessionLocal
from app.models.trigger_metric import TriggerDecisionCounter
from app.services.safety_metrics import today_kst

logger = logging.getLogger(__name__)

DECISION_FIRED = "fired"
DECISION_BLOCKED_TIER4 = "blocked_tier4"
DECISION_NO_CANDIDATE = "no_candidate"
DECISION_BLOCKED_MOOD = "blocked_mood"
DECISION_BLOCKED_COOLDOWN = "blocked_cooldown"
DECISION_BLOCKED_WEEKLY_CAP = "blocked_weekly_cap"
DECISION_NO_ROUTINE_MATCH = "no_routine_match"
DECISION_COLDSTART_BYPASS = "coldstart_bypass"


def _build_upsert(dialect_name: str, outcome: str, day: date):
    if dialect_name == "sqlite":
        from sqlalchemy.dialects.sqlite import insert
    else:
        from sqlalchemy.dialects.postgresql import insert

    stmt = insert(TriggerDecisionCounter).values(
        outcome=outcome, day_bucket=day, count=1
    )
    # updated_at 수동 갱신 — TimestampMixin의 onupdate는 Core upsert에 발동하지 않는다.
    return stmt.on_conflict_do_update(
        index_elements=["outcome", "day_bucket"],
        set_={
            "count": TriggerDecisionCounter.count + 1,
            "updated_at": datetime.now(UTC),
        },
    )


async def record_trigger_decision(
    outcome: str, *, session_factory=AsyncSessionLocal
) -> None:
    """트리거 결정 카운터 +1. 실패해도 호출자에 예외를 전파하지 않는다."""
    try:
        async with session_factory() as db:
            dialect_name = db.bind.dialect.name
            await db.execute(_build_upsert(dialect_name, outcome, today_kst()))
            await db.commit()
    except Exception:
        logger.warning("trigger decision metric drop: %s", outcome)
```

MIN_BASELINE_OBS = 7      # mood 기준선 산출 최소 관측 수
BASELINE_WINDOW = 30      # 기준선 표본 상한
MIN_MOOD_STDEV = 0.5      # 표준편차 하한 — 1~5 정수 척도에서 과민 방지
MOOD_SENSITIVITY_L = 1.0  # 민감도 노브 — 근거로 도출된 값이 아니며 M2 지표로 조정


def compute_mood_baseline(prior_moods: list[int]) -> tuple[float, float] | None:
    """현재 일기를 제외한 본인 과거 mood로 (평균, 변동)을 낸다.

    관측이 MIN_BASELINE_OBS 미만이면 None(콜드스타트) — 호출부가 게이트를 우회한다.
    집단 임계치·임상 컷오프를 쓰지 않는다.
    """
    if len(prior_moods) < MIN_BASELINE_OBS:
        return None
    sample = prior_moods[:BASELINE_WINDOW]
    return mean(sample), max(stdev(sample), MIN_MOOD_STDEV)


def passes_mood_gate(
    current_mood: int,
    baseline: tuple[float, float] | None,
    sensitivity: float = MOOD_SENSITIVITY_L,
) -> bool:
    """현재 mood가 개인 기준선 대비 충분히 낮으면 True. 콜드스타트(None)는 우회."""
    if baseline is None:
        return True
    baseline_mean, baseline_std = baseline
    return current_mood <= baseline_mean - sensitivity * baseline_std
```

### 설계 대비 의도적 축소 (계측 범위)

설계 §3.5는 결정 로그에 "발동/무발동 + 차단 게이트 + **사용된 신호**(후보 키워드, mood 편차값, 콜드스타트 여부)"를 남기라고 적는다. 본 계획은 이 중 **발동/무발동·차단 게이트·콜드스타트 여부**만 기록한다.

- **이유**: 카운터는 익명 사전집계 `(outcome, day_bucket, count)` 구조라 연속값(mood 편차)이나 사용자별 키워드를 담을 수 없다. 담으려면 차원을 늘려야 하고, 이는 익명성·물리적 분리 원칙과 상충할 위험이 있다.
- **대체 관측**: 발동 시 키워드 분포는 기존 `TriggerLog` 기반 `trigger_activity_stats`의 `triggers_by_keyword`로 이미 관측된다.
- **충분성**: L 튜닝에 필요한 신호는 `blocked_mood` 대비 `fired` 비율이며, 이는 본 계획의 카운터로 관측 가능하다. 편차값 분포가 필요해지면 별도 과제로 버킷화(예: 0.5σ 구간) 방안을 검토한다.
