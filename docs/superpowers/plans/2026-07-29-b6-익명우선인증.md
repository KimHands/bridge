# B6 익명-우선 인증 + 선택적 승격 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 로 태스크 단위 실행. 각 스텝 `- [ ]`.

**Goal:** 이메일/비번 없이 기기 익명 계정으로 즉시 시작 → 이메일+비번(인증)으로 선택 승격(데이터 보존). 데이터는 서버 유지.

**Architecture:** User 모델에 익명 필드 추가 → `POST /auth/anonymous`(생성/재인증) → `POST /auth/upgrade`+`/auth/verify-email`(Redis TTL 코드) → 이메일 발송 어댑터(콘솔/향후 SMTP) → 모바일 익명 부트스트랩 + 승격 UI.

**Tech Stack:** FastAPI, SQLAlchemy async + Alembic, redis.asyncio, pytest; React Native/Expo(TS), expo-secure-store.

## Global Constraints
- `device_secret_hash = SHA-256(device_secret)`, **UNIQUE 인덱스(조회용)**. device_secret은 256-bit 랜덤이라 SHA-256 충분. `password_hash`는 bcrypt 유지.
- `email_hash`·`password_hash` → **nullable**(익명 NULL). Postgres는 NULL 다중 허용이라 unique 유지 가능.
- 신규 컬럼: `is_anonymous`(default true), `device_secret_hash`(nullable unique), `email_verified`(default false). 기존 행 백필: `is_anonymous=false, email_verified=true`.
- 승격 시 **동일 user.id 유지**(데이터 FK 보존).
- plaintext email+코드는 Redis TTL(10분) 임시 보관, verify 성공 시 삭제. email_hash(SHA-256)만 영속.
- 이메일 발송은 **어댑터 추상화**: 지금 `ConsoleEmailSender`(코드 로깅), config `EMAIL_BACKEND`로 향후 SMTP 교체.
- 사용자 노출 금지어(치료/진단/개선/효과) 없음. 응답 엔벌롭 `{success, data, message}`.
- 기존 `core/security.py`(hash_email/hash_password/verify_password/create_access_token/create_refresh_token) 재사용.

```python
import hashlib, secrets

def hash_device_secret(secret: str) -> str:
    return hashlib.sha256(secret.encode()).hexdigest()

def generate_verification_code() -> str:
    return f"{secrets.randbelow(1_000_000):06d}"
```

- [ ] **Step 1: 실패 E2E 테스트** — (a) 최초 호출 → 201 + 익명 User 생성(is_anonymous=true), (b) 동일 device_secret 재호출 → 같은 user_id 반환(재인증), (c) 다른 secret → 다른 user.
- [ ] **Step 2~4:** 구현

```python
@router.post("/anonymous", status_code=201, response_model=SuccessResponse[TokenResponse])
async def anonymous(body: AnonymousRequest, db: AsyncSession = Depends(get_db)):
    dsh = hash_device_secret(body.device_secret)
    user = (await db.execute(select(User).where(User.device_secret_hash == dsh))).scalar_one_or_none()
    if user is None:
        user = User(nickname=body.nickname or "익명",
                    is_anonymous=True, device_secret_hash=dsh)
        db.add(user); await db.commit(); await db.refresh(user)
    requires_assessment = (await db.execute(
        select(Assessment).where(Assessment.user_id == user.id).limit(1))).scalars().first() is None
    access, _ = create_access_token(str(user.id))
    refresh, _ = create_refresh_token(str(user.id))
    await set_refresh_session(str(user.id), refresh)
    return {"success": True, "data": TokenResponse(user_id=str(user.id), nickname=user.nickname,
            access_token=access, refresh_token=refresh, requires_assessment=requires_assessment), "message": "ok"}
```
`schemas/auth.py`: `AnonymousRequest(device_secret: str, nickname: str | None = None)`.
- 라이브 E2E로 3분기 확인 → 전체 회귀 → 커밋.

**Files:**

- Test: `backend/tests/test_auth_upgrade.py` (라이브 E2E)

**Interfaces:**
- Consumes: `hash_email`, `hash_password`, `generate_verification_code`, `get_email_sender`, `get_current_user`, redis.
- Produces: 3 엔드포인트. redis 헬퍼 `set_pending_verify(user_id, email, code, ttl)`, `get_pending_verify(user_id)`, `del_pending_verify(user_id)`.

- [ ] **Step 1: 실패 E2E** — 익명 사용자: (a) upgrade → email_hash 세팅·is_anonymous=false·email_verified=false, **기존 일기 데이터 보존**(같은 user.id), (b) 이미 존재 이메일 → 409, (c) verify-email 코드 일치 → email_verified=true·redis 삭제, (d) 이미 승격된 계정 upgrade → 409.
- [ ] **Step 2~4:** 구현(핵심)

```python
@router.post("/upgrade", response_model=SuccessResponse[dict])
async def upgrade(body: UpgradeRequest, current_user: User = Depends(get_current_user),
                  db: AsyncSession = Depends(get_db)):
    if current_user.email_hash is not None:
        raise HTTPException(409, {"code": "ALREADY_UPGRADED", "message": "이미 계정이 연결돼 있어요"})
    eh = hash_email(body.email)
    if (await db.execute(select(User).where(User.email_hash == eh))).scalar_one_or_none():
        raise HTTPException(409, {"code": "EMAIL_ALREADY_EXISTS", "message": "이미 사용 중인 이메일이에요"})
    current_user.email_hash = eh
    current_user.password_hash = hash_password(body.password)
    current_user.is_anonymous = False
    await db.commit()
    code = generate_verification_code()
    await set_pending_verify(str(current_user.id), body.email, code, ttl=600)
    await get_email_sender().send_code(body.email, code)
    return {"success": True, "data": {"email_verified": False}, "message": "인증 코드를 보냈어요"}

@router.post("/verify-email", response_model=SuccessResponse[dict])
async def verify_email(body: VerifyEmailRequest, current_user: User = Depends(get_current_user),
                       db: AsyncSession = Depends(get_db)):
    pending = await get_pending_verify(str(current_user.id))
    if not pending or pending["code"] != body.code:
        raise HTTPException(400, {"code": "INVALID_CODE", "message": "코드가 올바르지 않거나 만료됐어요"})
    current_user.email_verified = True
    await db.commit()
    await del_pending_verify(str(current_user.id))
    return {"success": True, "data": {"email_verified": True}, "message": "확인됐어요"}
```
`resend-verification`: pending 있으면 새 코드 재발송(레이트리밋은 잠정 생략, 백로그). redis 헬퍼는 `encrypt_json` 있으니 JSON setex 사용.
- 라이브 E2E(데이터 보존 포함) → 전체 회귀 → 커밋.
