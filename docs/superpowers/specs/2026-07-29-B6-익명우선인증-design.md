# B6 — 익명-우선 인증 + 선택적 승격 설계

> 작성: 2026-07-29 · 상태: 승인됨(브레인스토밍) → 구현 플랜 대상
> 근거: `참고파일/2026-07-22_리서치_인증대체_저장방식.md`, `참고파일/2026-07-22_B1B7_결정및반영.md`(B6 결정)
> 결정: 익명-우선 + 선택 승격(옵션1). 로컬-우선 저장은 범위 밖. 승격 자격은 이메일+비번(옵션A). 이메일 발송은 지금 어댑터-C(콘솔), 향후 B(SMTP).

## Goal
회원가입 마찰·이메일 미검증·프라이버시 우려(3차 세미나 승우 피드백)를 해소한다. 사용자는 이메일/비번 없이 **기기 익명 계정**으로 즉시 시작하고, 원할 때 **이메일+비밀번호(인증 포함)로 승격**해 계정 복구·멀티기기를 얻는다. 감정·일기 데이터는 **서버(Postgres) 유지**(트리거 개인 기준선·리포트·미션이 서버 히스토리에 의존하므로).

## 핵심 설계 결정
1. **익명-우선**: 첫 실행 시 이메일/비번 없이 기기 익명 계정 생성.
2. **선택적 승격**: 이메일+비번으로 승격(강제 아님), 동일 user.id 유지로 데이터 보존.
3. **이메일 인증**: 코드 방식, 발송은 추상화된 어댑터(지금 콘솔, 향후 SMTP).
4. **데이터는 서버 유지**(로컬-우선 제외).

## 아키텍처

### 익명 신원 메커니즘
- 클라이언트가 첫 실행 시 랜덤 `device_secret`(256-bit, base64) 생성 → SecureStore 저장.
- `POST /v1/auth/anonymous {device_secret, nickname?}` → 백엔드가 `User(is_anonymous=True, email_hash=NULL, password_hash=NULL, device_secret_hash=sha256(device_secret), email_verified=False)` 생성 → JWT access+refresh 발급(기존과 동일).
- **재인증**: refresh 소실/만료 시 클라이언트가 동일 `device_secret`로 `POST /auth/anonymous` 재호출 → `device_secret_hash` 매칭되는 기존 익명 User 찾아 재로그인(신규 생성 아님). 매칭 없으면 신규 생성.
- **트레이드오프**: SecureStore 소실(앱 삭제/기기 변경) 시 익명계정 복구 불가 → 승격이 해법. 앱이 자연스러운 순간에 안내(강제 없음).

### User 모델 변경 (마이그레이션)
- `email_hash`: `nullable=True`로 변경(익명은 NULL). `unique` 제약은 유지하되 NULL 다중 허용(Postgres는 NULL 중복 허용).
- `password_hash`: `nullable=True`로 변경.
- 신규 컬럼: `is_anonymous BOOL NOT NULL DEFAULT true`, `device_secret_hash VARCHAR(64) NULL UNIQUE`(SHA-256, **조회용 인덱스**), `email_verified BOOL NOT NULL DEFAULT false`.
  - ⚠️ device_secret은 256-bit 랜덤(저엔트로피 비밀번호 아님)이라 SHA-256이면 충분하고, bcrypt와 달리 **해시로 O(1) 조회**가 가능하다(재인증 시 device_secret_hash로 User 직접 lookup). password_hash(사용자 비번)만 bcrypt 유지.
- **기존 사용자 백필**: 마이그레이션에서 기존 행(email_hash NOT NULL) → `is_anonymous=false, email_verified=true`.

### 승격 흐름 (익명 → 이메일 계정)
1. `POST /v1/auth/upgrade {email, password}` (인증된 익명 사용자만; 이미 email_hash 있으면 409):
   - 이메일 중복 확인(email_hash unique).
   - 동일 `user.id`에 `email_hash=sha256(email)`, `password_hash=bcrypt(password)` 세팅, `is_anonymous=false`. **데이터(diaries·assessments·routines)는 FK가 user.id라 그대로 보존.**
   - 인증 코드(6자리) 생성 → `email_verified=false` 유지 → 발송 어댑터로 코드 전달. plaintext email + 코드는 **Redis에 TTL(예 10분) 임시 보관**(`verify:{user_id}` → {email, code}).
2. `POST /v1/auth/verify-email {code}` → Redis 코드 매칭 시 `email_verified=true`, Redis 키 삭제(plaintext email 파기, email_hash만 영속).
3. 승격 후 로그인은 **기존 `POST /auth/login {email, password}`** 경로 사용(멀티기기·복구).
4. 코드 재발송: `POST /v1/auth/resend-verification` (레이트리밋).

### 이메일 발송 어댑터 (추상화)
- `app/services/email_sender.py`: `EmailSender` 프로토콜(`async def send_code(email: str, code: str)`).
- **지금**: `ConsoleEmailSender` — 코드를 로거로 출력(dev), 필요 시 응답 디버그 필드(비운영). 실제 발송 없음.
- **향후(계획)**: `SmtpEmailSender`(옵션 B, SMTP) — 어댑터 교체만. config `EMAIL_BACKEND`로 선택.

### 모바일
- 온보딩: 회원가입 강제 제거 → 첫 진입 시 익명 계정 자동 생성("바로 시작"). 기존 로그인/회원가입 화면은 유지(승격·기존 사용자용).
- 승격 유도: 마이페이지에 "계정 만들기(기록 지키기)" 메뉴 + 자연스러운 소프트 배너(강제 없음).
- 승격 화면: 이메일+비번 입력 → 인증코드 입력 화면. 성공 시 email_verified.
- `device_secret` 생성·SecureStore 저장·anonymous 부트스트랩을 auth store에 추가.

## 에러/엣지케이스
- device_secret 없음(첫 실행) → 생성. 있음 → 재인증.
- 승격 시 이메일 이미 사용 중 → 409.
- 이미 승격된 계정이 upgrade 재호출 → 409.
- 인증 코드 만료(TTL) → 재발송 안내.
- Redis 다운 → 승격 자체는 성공(email_hash 세팅)하되 인증은 재시도(email_verified=false 유지); 발송 실패 로깅.
- 익명 사용자도 회원탈퇴(기존 삭제 경로) 동작.

## 규제/보안
- 익명이 프라이버시 강점: 서버에 신원 정보 없음(신원↔감정 분리 원칙 강화).
- plaintext email은 인증 완료까지만 TTL 보관 후 파기, email_hash(SHA-256)만 영속.
- device_secret은 SHA-256 해시로만 저장(원문 미저장·조회용). 256-bit 랜덤이라 사전공격 무의미. password_hash는 bcrypt. 사용자 노출 문구 금지어 없음.

## 테스트
- 익명 생성/재인증(device_secret 매칭·비매칭), 승격(데이터 보존·email 세팅·중복 409·이미승격 409), 이메일 인증(코드 검증·만료·재발송), 어댑터(콘솔 캡처), 백필 마이그레이션. 라이브 Postgres E2E(익명→일기작성→승격→데이터 유지 확인).

## 범위 밖 (YAGNI / 향후)
- 로컬-우선 저장(별도 대형 과제).
- OIDC(Sign in with Apple/Google)·패스키 승격.
- 실제 이메일 발송(옵션 B, SMTP) — 어댑터 교체로 전환(**실사용 구현 시 계획**).

## 미해결·튜닝
- 인증 코드 TTL(10분)·재발송 레이트리밋은 잠정값.
- 익명계정 방치 정리 정책(장기 미사용 익명계정 파기)은 향후.
