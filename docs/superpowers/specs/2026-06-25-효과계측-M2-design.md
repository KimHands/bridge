# M2 효과 계측 — 운영자용 익명 사용 지표 (설계)

> **작성일**: 2026-06-25 · **백로그**: 잔여백로그 §4 M2 · **연계**: M1([[project_m1_safety_metrics]]) 패턴, M3 트리거 근거
> **성격**: 운영자용 완전익명 집계. 사용자 노출·효과 주장 없음.

## 목적
루틴 지속·트리거 작동·정서 분포를 운영자가 추적할 수 있게 한다. "측정 가능한가"(S4) 공백을 닫는다. 규제 제약상 사용자에게 효과·개선을 표방하지 않으며, 개인 식별 없는 집계만 제공한다.

## 접근 (Y: 온디맨드 집계)
세 지표의 원천(`routine_logs`·`user_routines`·`assessments`·`trigger_logs`)은 **이미 영속**된다. 따라서 신규 카운터 테이블·쓰기 없이 **기존 테이블을 읽어 집계**한다.
- 장점: 과거 데이터까지 분석, 중복 저장 0, 분석 데이터 자체를 저장하지 않는 프라이버시 바이 디자인.
- M1의 "적재만 + SQL조회" 운영 모델과 일관 — 엔드포인트·admin 인증 없이 운영자 스크립트로 조회.

## 컴포넌트
| 파일 | 책임 |
|------|------|
| `app/services/usage_metrics.py` | 비동기 집계 함수 3개. 읽기 전용, 무쓰기. KST 일자 버킷은 Python에서(방언안전, M1과 동일 철학). 예상 규모상 필요한 컬럼만 풀스캔 후 집계. |
| `scripts/usage_report.py` | 운영자 CLI. AsyncSessionLocal로 세션 열고 기간(기본 30일) 집계 출력. `python -m scripts.usage_report --days 30` |
| `tests/test_usage_metrics.py` | SQLite에 필요한 `__table__`만 생성(ARRAY 충돌 회피), 알려진 데이터로 집계 단언 |

## 함수 시그니처·반환
모두 `async def f(db: AsyncSession, start: date, end: date) -> dict` (start·end 포함 구간, KST 기준).

1. **routine_completion_stats** — `routine_logs.completed_date`(완료) + `user_routines.is_active`(분모)
   - `total_completions`, `daily_completions{date:count}`, `distinct_completed_routines`, `active_routines_now`, `approx_completion_rate`(=총완료/(활성×일수), 활성 0이면 None)
   - **한계**: 과거 활성 스냅샷이 없어 완료율은 '현재 활성' 기준 근사. 일별 완료 수는 정확.
2. **trigger_activity_stats** — `user_routines.source`/`assigned_at` + `trigger_logs.created_at`/`triggered_keyword`
   - `assignments_by_source{initial,trigger,manual}`, `daily_triggers{date:count}`, `triggers_by_keyword{kw:count}`, `total_triggers`
3. **assessment_tier_distribution** — `assessments.phq_tier` + `created_at`
   - `by_tier{1..4}`, `daily_by_tier{date:{tier:count}}`, `total`
   - **한계**: 개인 변화 아닌 모집단 분포(익명). 개선 추론 불가.

## 데이터 흐름·에러
읽기 전용. 데이터 없으면 0/빈 dict. 스크립트는 예외 시 메시지 출력 후 비정상 종료 코드.

## 테스트 전략
SQLite in-memory(conftest sys.path). `RoutineLog`·`UserRoutine`·`Assessment`·`TriggerLog`의 `__table__`만 생성(FK off, ARRAY 보유한 `routines` 테이블 회피). KST 경계(자정 전후) 버킷 분류, source별 분리, tier별 분리, 빈 구간 0 반환을 단언.

## 범위 밖
사용자 노출, 엔드포인트, admin 인증, 카운터 테이블, 마이그레이션, 코호트 리텐션(완전익명이라 개인 추적 불가).
