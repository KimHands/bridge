> **브랜치**: `feat/logic-seed-supplement`
> **기준**: [적대적검증 잔여백로그](../../01-plan/2026-06-03-적대적검증-잔여백로그.md)

## 1. 목적

적대적검증 백로그 L1~L5(로직·시드 enhancement)를 항목별로 판단해, 가치 대비 위험이 낮고 규칙 정합성을 해치지 않는 것만 진행한다.

## 2. 항목별 결정 (C: 항목별 판단)

| ID | 결정 | 근거 |
|----|------|------|
| **L1** 4구간 전용 루틴 | **보류** | 4구간은 트리거 비활성(전문가 연계). 초기배정도 limit(1) 고정. "최소 부담 1개" 의도와 역행, 추가 시 배정 로직까지 변경 필요 |
| **L2** 긍정 트리거 루틴 | **진행** | 순수 보충. 긍정 루틴이 tier 1-1뿐이라 2~3구간 트리거 시 빈손 |
| **L3** 세부질문 | **본래 보류 + 가드 테스트로 대체** | KEYWORD_META에 8감정×(1질문+4선지) 이미 완비. 다단계/DB화는 모바일 동반·가치 불명확. 대신 노출 콘텐츠 금지어 가드 테스트 추가(실질 안전 가치) |
| **L4** 미션 부분노력 보상 | **진행** | 동기 설계상 가치 큼(S5 연결). 구성요소별 게이트로 부분보상+꾸준함게이트 양립 |
| **L5** 키워드 균형 | **보류** | 8개는 임상척도(PHQ-9/GAD-7) 근거 기반. 추가는 근거 검토 선행 + 연쇄변경(메타·루틴·CLAUDE.md). 별도 임상·제품 사이클 |

## 3. L2 — 긍정 강화 루틴 2개 신규 시드

`app/seeds/routines.py`의 `ROUTINE_SEEDS`에 2개 추가:

| title | phq_tier_min | phq_tier_max | target_keywords |
|---|:---:|:---:|---|
| 오늘 뿌듯했던 순간 떠올려 메모하기 | 1 | 3 | `["뿌듯한"]` |
| 좋아하는 음악 한 곡 듣기 | 1 | 3 | `["평온한"]` |

- `description`은 기존 루틴 톤에 맞춰 짧은 안내문(규제 표현 금지).
- 기존 1구간 긍정 루틴(오늘 잘한 일 적기 / 10분 독서)은 **보존** — 시드 식별 키가 `title+tier_min+tier_max`라 tier 범위를 넓히면 orphan 중복이 생기므로, 신규 추가가 정답.
- tier 1-3이라 2~3구간 사용자가 '뿌듯한'/'평온한'을 7일 중 3회+ 기록해 트리거될 때 `keyword == any_(target_keywords)` 매칭(routine_trigger.py:213-227)으로 빈손 해소.
- cause 키워드(future 등)는 넣지 않음 — 긍정 루틴은 초기배정(primary_cause 매칭) 대상이 아닌 트리거 강화 전용.
- 4구간은 트리거 비활성이라 tier_max=3으로 충분.

## 4. L4 — 미션 구성요소별 3일 게이트

`app/api/v1/missions.py` 점수 계산을 게이트 세분화:

```python
routine_component = round(routine_days / 7 * 70) if routine_days >= 3 else 0
diary_component   = round(diary_days   / 7 * 30) if diary_days   >= 3 else 0
weekly_score = routine_component + diary_component
is_achieved  = routine_days >= 3 or diary_days >= 3   # 한쪽이라도 3일+면 달성
total_score  = historical_total + weekly_score        # weekly_score 그대로 적립
```

기존: `is_achieved = routine_days >= 3 AND diary_days >= 3`, 미달 시 `weekly_score`를 통째로 0 적립.
변경: 게이트를 각 component 안으로 이동. 한쪽만 3일+여도 그 부분 점수는 적립.

결과:
| 케이스 | 변경 후 |
|---|---|
| 루틴 3일+ / 일기 0 | 루틴점수만 (예 round(3/7*70)=30) |
| 일기 3일+ / 루틴 0 | 일기점수만 (예 round(3/7*30)=13) |
| 둘 다 3일+ | 전액 |
| 둘 다 미달 | 0 (차감 없음, 기존 유지) |

기존 상수 `_ACHIEVE_ROUTINE_MIN`/`_ACHIEVE_DIARY_MIN`의 용도는 구현 시 확인해 정합되게 반영(표시/판정 용도면 유지, 죽은 코드면 정리).

## 5. L3 — 노출 콘텐츠 금지어 가드 테스트

신규 `tests/test_content_domain_safe.py`:
- **루틴 title 전체**: `ROUTINE_SEEDS`의 모든 `title`(신규 2개 포함)에 `assert_domain_safe()` 적용 → 통과 검증.
- **감정 세부질문/선택지**: `KEYWORD_META`의 각 `question` + 모든 `answers`에 `assert_domain_safe()` 적용.
- **제외**: 감정 키워드 이름(`name`, "우울한" 등)은 테스트 대상에서 **제외**. `_BANNED_TERMS`의 "우울"에 의도된 정서 어휘가 부분일치로 걸리므로. 테스트에 주석으로 근거 명시.
- `assert_domain_safe`는 `app/services/notification.py`에 정의됨.

향후 루틴/질문 콘텐츠 추가 시 금지어 회귀를 자동 차단(메모리 [[feedback_domain_banned_terms_pattern]] 일치).

> 리스크: 기존 시드 중 가드 위반이 있으면 테스트가 빨갛게 됨 → 진짜 위반이므로 콘텐츠 수정. 계획에서 "기존 전부 통과"를 먼저 확인.

## 6. CLAUDE.md 갱신

"미션 시스템 점수 규칙" 블록을 구성요소별 게이트로 수정:
```
주간 점수 = 루틴 달성 70% + 일기 작성 30% (각 구성요소 독립 적립)
구성요소별 최소 기준: 루틴 7일 중 3일+이면 루틴 점수, 일기 7일 중 3일+이면 일기 점수 적립
양쪽 미달 시: 0점 (차감 없음)
```
다른 규칙은 불변.
