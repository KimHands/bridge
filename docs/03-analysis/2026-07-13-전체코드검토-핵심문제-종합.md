## 🟠 HIGH

### H1. 미션 누적점수가 주마다 감소 (AND게이트 ↔ OR게이트 모순)
- **위치**: `backend/app/api/v1/missions.py:74-76`, `:110`
- **내용**: 현재 주는 독립 적립(OR)로 계산되나, 과거 누적은 `routine_score>=30 AND diary_score>=13`인 주만 합산. 한쪽만 달성한 주의 획득 점수가 통째로 누락됨.
- **재현**: 3주간 루틴 매일·일기 0 → 각 주 저장은 `total=70`이나 누적은 `70>=30 AND 0>=13 → False`로 0점. 이번 주엔 70으로 보이다 다음 주 넘어가면 사라져 **누적 총점이 감소**. CLAUDE.md "각 구성요소 독립 적립, 양쪽 미달 시 0점"과 충돌.

### H2. APScheduler가 `--workers 2`에서 중복 실행 → 푸시 중복 발송
- **위치**: `backend/entrypoint.prod.sh:8-11`, `backend/app/main.py:46-52`
- **내용**: `scheduler.start()`가 lifespan 안에 있어 워커마다 실행. 루틴 리마인더(5분)·넛지·미션·자가평가 알림이 전 사용자에게 2회씩 발송.
- **조치**: 스케줄러를 웹 워커와 분리된 전용 단일 프로세스로.

### H3. 로그아웃/로그인 후 푸시 토큰 재등록 실패
- **위치**: `mobile/src/hooks/usePushNotifications.ts:44,60`, `mobile/src/navigation/Navigation.tsx:120`
- **내용**: `NotificationBridge`가 네비게이터 형제라 로그아웃/로그인해도 언마운트되지 않아 `lastTokenRef` 유지 → 재로그인 시 동일 토큰이라 `registerToken()` 건너뜀. 로그아웃 때 서버가 토큰을 비활성화했는데 재등록 없음.
- **영향**: 앱 프로세스 완전 종료·재실행 전까지 모든 푸시가 조용히 미도착.

### H4. Redis 인증 부재 (dev·prod 모두)
- **위치**: `docker-compose.yml`, `docker-compose.prod.yml`, `.env.production.template`
- **내용**: `requirepass` 없음, dev는 6379를 호스트 노출. Redis에 JWT 블랙리스트·리프레시 세션·암호화 챗 세션 존재 → `DEL blacklist:*`로 로그아웃/탈퇴 토큰 부활, 세션 위조 가능. (backlog O2 확인)

### H5. AES-256-GCM 단일 정적 마스터키 — AAD·로테이션 없음
- **위치**: `backend/app/core/encryption.py:10-32`
- **내용**: 전 사용자 일기+자가평가+챗을 키 하나로 암호화. IV는 매번 랜덤(양호)이나 키 로테이션·`user_id` 바인딩(AAD) 부재. 키 1회 유출(C1)로 전체 복호화. AAD 없어 DB 쓰기 권한자가 타 사용자 암호블롭 이전 후 API로 복호화 가능.

## 검증되어 문제 없음(참고)

- IDOR/SQLi: 모든 엔드포인트 인증+소유권 검사, 전 쿼리 파라미터라이즈드 — 안전
- JWT: HS256 + type claim + jti 블랙리스트 + 리프레시 로테이션 — 정상
- bcrypt cost 12, AES-GCM IV 매회 랜덤(nonce 재사용 없음)
- 계정 삭제 CASCADE: 자식 테이블 전부 `ON DELETE CASCADE` + Redis 세션 명시 삭제 — 모델상 정상(단, E2E 테스트는 없음 → M12)
- 모바일 401 리프레시 인터셉터 단일비행+큐 — 루프 없음, 낙관적 토글 롤백 정상
- 모바일 typecheck(`tsc --noEmit`) 클린
- PHQ 점수·tier명 **모바일 화면 노출 없음**(친화 카피만) — 단, API 응답엔 tier 노출(M3)

## 우선순위 제안

1. **즉시** — C1 시크릿 로테이션 + 문서 값 제거 (라이브 유출)
2. **데이터 정합성/신뢰** — H1 미션 누적, H3 푸시 재등록, M1 캐시 미삭제
3. **운영 안정성** — H2 스케줄러 중복, H4 Redis 인증, H5 AES 하드닝
4. **R1(M2 트리거 재설계)** — 데이터 손상은 아니고 "설계 의도 미작동" 문제. 위 급한 항목 후 브레인스토밍으로 재설계

> 메모리엔 컴플라이언스 수정·검증이 완료로 기록되어 있으나, 본 검토에서 C1·M3·M4 등 규제/보안 공백이 잔존함을 확인함. 백로그(R1·O1~O3)와 본 리포트를 함께 트래킹할 것.
