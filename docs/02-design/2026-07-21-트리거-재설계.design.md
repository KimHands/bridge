# 트리거 알고리즘 재설계 (R1 / 검토 M2)

> **작성일**: 2026-07-21 · **대상 코드**: `backend/app/routine_trigger.py`
> **선행 문서**: `docs/01-plan/2026-06-25-트리거-파라미터-근거.md`(M3), `docs/03-analysis/2026-07-13-전체코드검토-핵심문제-종합.md`(M2=R1)
> **목적**: 작동하지 않는 mood 가중치를 걷어내고, JITAI 문헌 근거에 기반한 게이트 구조로 트리거를 재설계한다.

---

## 1. 문제 정의

현행 `_calculate_trigger_score`는 명세상 "mood 30% + 키워드 빈도 70%"지만, **mood 가중은 수학적 no-op**이다.

```python
mood_component = (5 - mood_avg) / 5 * 0.3      # 그 실행의 모든 키워드에 동일한 상수
keyword_component = (freq / total_freq) * 0.7
trigger_scores[keyword] = mood_component + keyword_component
```

- 정렬 시 모든 후보에 **같은 상수**를 더하므로 순위가 절대 바뀌지 않는다.
- 발동 여부는 `freq >= 3`(빈도 컷)만으로 결정된다.
- **결론: 현재 스코어링 ≡ 빈도순 정렬.** mood_score의 기여도는 0이며 0.3/0.7 가중치는 장식이다.

기존 테스트 `test_lower_mood_yields_higher_score`는 *서로 다른 두 실행*을 비교해 통과하므로, "mood가 작동한다"는 착시를 만든다(한 실행 내 순위·발동에는 영향 없음).

### 2.3 외적 타당도 한계

- 근거 모집단: 미국·유럽 성인 흡연자(n=75), 신체활동 참가자(n=37~44), 만성질환 돌봄제공자(n=36), 외래 심리치료 희망 우울군(n=25). **한국 19~34세 비임상 청년 표본 없음.**
- 전부 소표본 실현가능성·최적화 연구이며 보고된 효과크기는 작다(d=0.06~0.14).
- **데이터 밀도 불일치가 가장 큰 이식 위험**: 근거 대부분이 하루 5~6회 EMA 또는 연속 센서 기반. **하루 최대 1건(주 3~7건)에서 검증된 트리거 규칙은 존재하지 않는다.**

## 3. 설계

### 3.1 결정 시점

일기 저장 직후 **1일 1회** 판정 (E1). 현행과 동일하되, "결정 시점"이라는 개념으로 명시화한다.

### 3.2 게이트 체인

순서대로 통과해야 배정하며, **어느 하나라도 막히면 "무발동"을 명시적 결정으로 기록**한다(E2).

| 게이트 | 규칙 | 근거 |
|--------|------|------|
| **G1 가용성** | PHQ 4구간 사용자는 트리거 대상 제외(전문가 연계 영역) — 현행 유지 | 현행 설계 |
| **G2 신호** | 키워드 반복 **AND** mood 편차 (§3.3) | E3, E7 |
| **G3 쿨다운** | 키워드별 3일 — 현행 유지 | E6 (단, 3일은 조작화) |
| **G4 주간 상한** | 트리거 배정 **최근 7일 롤링 기준 최대 2건** | E5, E6 |
| **G5 무발동** | 매칭 루틴이 없으면 무발동으로 기록 | E2 |

> 현행은 상위 2개 키워드 동시 발동 시 한 번에 2개를 배정할 수 있다(버스트). G4로 **주 단위 총량**을 묶어 습관화를 억제한다.

### 3.3 신호 규칙 — R1 해소의 핵심

**가중합을 폐기하고 독립 AND 게이트로 전환한다.**

```
후보 키워드 : 최근 7일 내 동일 키워드 ≥ 3회          (현행 유지)
mood 게이트 : 현재_mood ≤ 개인_기준선 − L × 개인_변동   (신규)
후보 순위   : 빈도 내림차순                          (가짜 정밀도 제거)
```

정확한 정의(구현 모호성 제거):

- **현재_mood** = 이번 결정 시점을 유발한 **그 일기의 `mood_score`** (개별값 관리도와 정합, E3).
- **개인_기준선** = 현재 일기를 **제외한** 본인 직전 기록 **최대 30건**의 `mood_score` 산술평균.
- **개인_변동** = 같은 표본의 **표본표준편차(ddof=1)**. 단, 표준편차가 0에 가까우면(모든 기록이 동일값) 게이트가 과민해지므로 **하한 0.5**를 적용한다(mood가 1~5 정수 척도임을 감안).
- **콜드스타트**: 현재 일기를 제외한 본인 기록이 **7건 미만**이면 mood 게이트를 **우회**하고 키워드 조건만 적용(= 현행 동작으로 폴백).
- **L은 문서화된 튜닝 노브**. 초기값 **L = 1.0**. 근거로 도출된 값이 아니며, E3에서 L 값이 발동량을 40% 좌우했음을 감안해 M2 지표로 사후 조정한다.

집단 임계치·임상 컷오프를 쓰지 않으므로 규제 포지셔닝과 정합한다(E3).

이로써 mood_score가 **발동 여부를 실제로 좌우**한다. "우울 3회지만 평소보다 나쁘지 않음" → 무발동, "우울 3회 + 평소보다 뚜렷이 낮음" → 발동.

가중합(weighted sum) 대신 AND 게이트를 택한 이유: 두 신호를 결합하는 방식에 대한 문헌 근거가 없고(§2.2), 임의 가중치가 바로 R1의 원인이었다. 해석 가능한 규칙이 방어에 유리하다.

### 3.4 사용자 요청 경로 (신규)

"지금 도움이 필요해요" 액션 → 즉시 루틴 추천. **동일한 쿨다운·주간 상한을 적용**한다.
E4가 가장 강한 단일 발견이며 구현 비용도 낮다.

> 단, E4에는 저자가 인정한 교란이 있다 — 요청 트리거는 377건 중 46건(12%)뿐이라 **낮은 발동 빈도 자체**가 높은 평가에 기여했을 수 있다. "요청 경로가 우월하다"가 아니라 "요청 경로를 **병행**할 근거가 있다"로 서술한다.

### 3.5 계측

결정 로그에 다음을 남겨 M2 운영 지표(`scripts/usage_report.py`)에 연결한다.

- 발동 / 무발동 여부
- 무발동 시 **차단된 게이트**(G1~G5)
- 사용된 신호(후보 키워드, mood 편차값, 콜드스타트 폴백 여부)

이는 L·주간 상한·쿨다운을 데이터로 조정하는 폐루프의 관측 축이며, E7의 "발동 조건은 실증 대상" 원칙에 대응한다. **모든 지표는 기존 방식대로 익명 사전집계**로 수집한다.

## 4. 파라미터 표 (근거 유무 명시)

| 파라미터 | 값 | 근거 상태 |
|----------|-----|-----------|
| 결정 시점 | 일기 저장 직후 1일 1회 | **문헌 지지**(E1) |
| 키워드 임계 | 7일 내 ≥ 3회 | 현행 유지, heuristic (임상 근거 없음) |
| mood 게이트 | 현재 mood ≤ 기준선 − L×변동 | **방법론 지지**(E3), 구체 임계는 미검증 |
| 기준선 표본 | 현재 일기 제외 직전 최대 30건 | **조작화** |
| 변동 하한 | 표준편차 하한 0.5 | **조작화** (1~5 정수 척도 과민 방지) |
| L (민감도) | 1.0 | **근거 없음 — 튜닝 노브**, M2로 조정 |
| 콜드스타트 최소 관측 | 7건 | E3의 7관측 베이스라인 차용. 단 E3는 하루 6회 EMA라 1~2일치, 본 서비스는 1~2주 소요 — **직접 이식 아님** |
| 쿨다운 | 키워드별 3일 | 현행 유지, **조작화**(직접 근거 없음) |
| 주간 상한 | 최근 7일 롤링 2건 | E5·E6 방향과 정합, 구체 수치는 **조작화** |

## 5. 단계적 롤아웃

| 단계 | 범위 |
|------|------|
| **Stage 1** | 가중치 제거, 게이트 체인 구조화(G1~G5), 주간 상한, 계측 |
| **Stage 2** | 사용자 요청 경로 (백엔드 + 모바일) |
| **Stage 3** | 개인 기준선 mood 게이트 + 콜드스타트 폴백 |

Stage 1은 발동 동작을 크게 바꾸지 않는 정직화·구조화이며, mood가 실제로 작동하기 시작하는 것은 Stage 3이다.

## 6. 비범위 (Non-goals)

- ❌ 임상 임계치·구간명 사용 (규제 포지셔닝)
- ❌ 이동평균 교차·변화점 탐지 — 조사에서 구체 근거 **기각**되었고 주 3~7건으로 데이터도 부족
- ❌ 상용 앱 트리거 모방 — 검증된 1차 출처 없음
- ❌ 효과 주장 — 근거는 전부 타 도메인·소표본이며 본 서비스 표본에서 검증되지 않음

## 7. 한계 및 리스크

1. **이식 위험**: 하루 1건 자기보고 밀도에서 검증된 트리거 규칙은 문헌에 없다. 본 설계는 방법론(구조·원칙)을 차용한 것이지 검증된 규칙의 복제가 아니다.
2. **콜드스타트 지연**: 주 3~7건 기록에서 개인 기준선 7건 확보에 1~2주가 걸린다. 그동안은 현행 키워드 규칙으로 동작한다.
3. **AND 게이트로 발동량 감소**: 의도된 방향(E2·E5·E6)이나, 과소 발동으로 사용자가 아무 추천도 못 받는 구간이 생길 수 있다. G4 상한과 함께 M2 지표로 모니터링한다.
4. **파라미터 임의성**: L·쿨다운·주간 상한은 모두 조작화된 값이다. "검증된 정답"이 아니라 **모니터링 가능한 출발점**으로 문서화한다(선행 M3 문서의 결론과 동일한 태도).

## 8. 성공 기준

- mood_score가 발동 결정에 **실제로 영향을 준다**(동일 키워드 빈도에서 mood 편차에 따라 발동/무발동이 갈리는 것을 테스트로 고정).
- 무발동 결정이 **기록**되어 차단 게이트 분포를 관측할 수 있다.
- 주간 배정이 상한(2건)을 초과하지 않는다.
- 근거 없는 가중치가 코드·문서에서 제거된다.
