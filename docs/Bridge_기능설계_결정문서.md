## A. 키워드 기반 일기 설계

### A-1. 감정 키워드 구조

- **분류 방식**: 1단계 이모지 선택 → 2단계 세부 감정 키워드 선택
- **공통 풀**: 8개 키워드, 이모지별 하이라이트 2~3개 상단 노출
- **복수 선택**: 최대 2개까지 허용
- **mood_score 연동**: 이모지 선택 시 mood_score(1~5) 자동 저장, 키워드는 별도 저장 → 둘 다 루틴 트리거에 활용

### A-2. 감정 키워드 목록 (논문 근거 기반)

| 키워드 | 근거 척도 |
|--------|---------|
| 우울한 | PHQ-9 핵심 증상 |
| 무기력한 | PHQ-9 (에너지 저하) |
| 불안한 | GAD-7 핵심 증상 |
| 초조한 | PHQ-9·GAD-7 공통 중개 증상 (아산시 청년 정신건강실태조사, 2022) |
| 짜증나는 | GAD-7 (과민성) |
| 외로운 | 청년 고립감 연구 핵심 변수 |
| 뿌듯한 | 긍정 정서 (대조군) |
| 평온한 | 긍정 정서 (대조군) |

### A-3. 이모지별 하이라이트 키워드

| 이모지 | 하이라이트 키워드 |
|--------|----------------|

| 🙂 좋음 | 평온한 · 뿌듯한 |

### A-4. 감정 키워드별 질문지 (논문 근거 기반)

각 감정 키워드 선택 시 해당 키워드에 맞는 세부 질문이 팝업되며, 답변 선택지가 상황 키워드로 저장된다.

## B. 자가평가 → 초기 루틴 규칙 설정

### B-1. PHQ-9 점수 구간

PHQ-9 공식 4구간 기준 적용.

| 구간 | 점수 범위 | 내부 라벨 |
|------|----------|------|
| 1구간 | 0~4점 | 안정 신호 |
| 2구간 | 5~9점 | 가벼운 신호 |
| 3구간 | 10~19점 | 살펴볼 신호 |
| 4구간 | 20~27점 | 집중 돌봄 신호 |

> 구간은 PHQ-9 표준 절단점에 기반한 **내부 루틴 배정 파라미터**이며, 임상 진단 범주가 아니다. 사용자에게는 점수·구간·라벨을 노출하지 않는다.

### B-2. 원인 분류 질문 (PHQ-9 직후 추가)

PHQ-9 완료 직후 원인 분류 질문 2개를 이어서 진행한다.

- 💸 경제적인 걱정이 있어요

### B-4. 설계 원칙

- 4구간은 원인 무관 고정 — 중증 상태에서 선택 자체가 부담이므로 최소 과제 1개로 통일
- 감정 일기는 1·2구간에만 포함 — 3·4구간은 데이터 수집보다 회복 우선
- 부원인은 초기 배정에는 미사용, 이후 트리거 보조 조건으로만 활용
- 사용자가 언제든 루틴을 자유롭게 추가·삭제·교체 가능

## C. 루틴 트리거 알고리즘

### C-1. 발동 조건

- 관찰 기간: 최근 **7일**
- 발동 기준: 동일 감정 키워드 **3회 이상** 선택 시

### C-2. 가중치 구조

> ⚠️ **[대체됨 2026-07-21]** 아래 가중합은 mood 항이 모든 키워드에 동일 상수라 발동·순위에 영향이
> 없는 no-op이었다(R1). 게이트 체인(G1~G5) 기반 신규 설계로 대체됨 —
> `docs/02-design/2026-07-21-트리거-재설계.design.md` 참조. 아래는 이력 보존용 원안이다.

```
트리거 점수 = mood_score 기여분(30%) + 감정 키워드 기여분(70%)
```

- **mood_score 기여분**: `(5 - mood_avg) / 5 × 0.3` — 낮을수록 높은 점수
- **감정 키워드 기여분**: 키워드별 선택 빈도를 전체 빈도로 나눈 비율 × 0.7
- **키워드 내 가중치**: 선택 빈도 기반 동적 조정 — 자주 선택한 키워드일수록 가중치 증가

### C-3. 충돌 처리

여러 트리거가 동시에 조건을 충족하는 경우, 두 키워드를 모두 커버하는 **복합 루틴** 추천.
트리거 점수 상위 2개 키워드를 기준으로 복합 루틴 결정.

### C-4. 재발동 주기

한 번 트리거 발동 후 **3일** 이후 재발동 허용.

### C-5. 핵심 알고리즘 구조

```python
def calculate_trigger_score(diary_logs: list, days: int = 7) -> dict:
    recent_logs = diary_logs[-days:]
    keyword_freq = {}
    mood_avg = 0

    for log in recent_logs:
        mood_avg += log["mood_score"]
        for keyword in log["emotion_keywords"]:
            keyword_freq[keyword] = keyword_freq.get(keyword, 0) + 1

    mood_avg /= len(recent_logs)

    total_freq = sum(keyword_freq.values())
    keyword_weights = {k: v / total_freq for k, v in keyword_freq.items()}

    trigger_scores = {}
    for keyword, weight in keyword_weights.items():
        mood_component = (5 - mood_avg) / 5 * 0.3
        keyword_component = weight * 0.7
        trigger_scores[keyword] = mood_component + keyword_component

    return trigger_scores


def evaluate_triggers(trigger_scores: dict, freq: dict, threshold: int = 3) -> list:
    triggered = [k for k, v in freq.items() if v >= threshold]

    if len(triggered) == 0:
        return []
    elif len(triggered) == 1:
        return [triggered[0]]
    else:
        # 충돌: 점수 높은 순 2개 → 복합 루틴
        triggered_sorted = sorted(
            triggered,
            key=lambda k: trigger_scores.get(k, 0),
            reverse=True
        )
        return triggered_sorted[:2]
```

## D. 기분 체크 연동 범위

- 홈 기분 체크(이모지)와 일기 감정 키워드는 **완전 독립 저장**
- 이모지 선택 → `mood_score` 자동 저장
- 감정 키워드 → 별도 저장
- **둘 다** 루틴 트리거 알고리즘에 활용 (C-2 가중치 구조 참고)

---

## E. 긍정 미션 시스템

### E-1. 구조

- 단계 없이 **점수제** 운영
- 점수 배점: 루틴 완료 **70%** + 일기 작성 **30%**

### E-2. 주간 달성 기준

- 기준 기간: **7일**
- 최소 달성 일수: **3일 이상** (43%)
- 달성 시: 해당 주 점수 적립
- 미달성 시: 점수 **유지** (깎이지 않음, 해당 주만 적립 안 됨)

### E-3. 설계 의도

정신건강 앱에서 실패 패널티는 자책감을 유발할 수 있어 점수 차감 방식을 배제하고, 달성하지 못한 주간에도 기존 점수를 유지하도록 설계. 작은 성공 경험의 누적이 회복 동기로 이어지는 구조를 지향.
